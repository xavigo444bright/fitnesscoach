## 1. 文档目的

本 PRD 定义「健身动作指导」产品的需求、范围、验收标准与技术约束，供：

- **产品/设计**：对齐功能与优先级
- **开发（人）**：按模块分工与排期
- **AI 模型**：作为唯一需求真源（Single Source of Truth）进行实现与迭代

## 2. 产品概述

### 2.1 一句话描述

通过手机 App：**跟练纠错**（摄像头实时姿态）+ **训练记录**（容量/历史，对标训记一类记训应用）。帮助用户既做对动作，也留得下自己的训练量。

### 2.2 产品定位

| 维度 | 说明 |
|------|------|
| 品类 | AI 跟练纠错 + 训练日志（容量记录） |
| 核心差异化 | 实时姿态估计与纠错 + **一节课多动作记组/次/重量**（可无镜头；跟练仍保留）。容量 = 有重量组的次数×公斤 |
| 目标用户 | 居家与健身房自主训练者：既要动作对，也要记得住练了多少 |
| 最终交付形态 | **手机 App（iOS/Android）**。微信小程序已于 2026-09-07 放弃 |

### 2.3 目标与成功指标

### 4.6.2 训练页参考规格

> 真源约束：业务校验仍在 `packages/core`；身上与「骨骼」模式消费用户 Pose；样片模式播原片。**禁止**在 UI 层写相位/计数规则。

**数据流（必须）**

```
机位规格（camera-planes/specs.json，FR-089；新动作必填）
  → ASSET-SCOUT 清单（clips.json，须绑 scout-id）
  → 你确认授权
  → 示范样片（media/trajectory-source）
  → 离线提取（tools/，FR-067）
  → packages/core/trajectories
```

```typescript
// 动作定义
interface Exercise {

}

  issues: Issue[];
}

interface Session {
  id: string;
  exerciseId: string;
  startedAt: number;
  endedAt: number;
  reps: Rep[];
  topIssues: string[];
}
```

## 12. 术语表

| 术语 | 定义 |
|------|------|
| 容量 | 填了重量的组：`次数 × 公斤` 再加总。未填重量与计时动作不进该数字 |
| 记训 | 不开摄像头也能记下组/次/重量 |
| 课表 | 一次训练会话，内含多个动作（每个动作多组） |
| 2D 骨骼 | 细骨段连线 + 带白边的关节圆点（绿/黄/红）。FR-060 |
| 用户骨骼 | 跟自己实时姿态的 2D 骨骼；叠在摄像头上，贴合身体移动 |
| 示范骨骼 | 示范窗「骨骼」模式下参考人身上的 2D 骨骼，由示范轨迹驱动 |
| 参考人 | 示范窗骨骼模式里的标准体型人；跟相位、不贴身 |
| 样片轮播 | 示范窗默认模式：循环播放参考库原片（轨迹 `source.label`），独立时间轴；可暂停、调速，不跟用户相位 |
| 示范轨迹 | 从示范**样片**提取并清洗后的关节时间序列，按动作 ID 归档 |
| Plan C | 样片轨迹驱动的训练对照（现为示范骨骼 + 小窗参考人）；相对已否决的身上 3D 胶囊 |
| 3D rig | 由对齐后 Pose 驱动的关节+骨段+体积；非独立关键帧动画、非预渲染片 |
| 训记风格 | 风格化 3D 人形+肌肉色块/体积的动作示意；**训练页须实时关节驱动**，详情页预烘焙片仍为 FR-064（P2） |
| 评估动作 | 本阶段 3D 验收仅 **squat + pushup**（先 side） |
| Phase | 动作阶段（如深蹲底部） |
| Rep | 一次完整重复 |
| ROM | Range of Motion，动作幅度 |
| 容差 | 规则允许的误差范围（度或比例） |
| visibility | 关键点可见度置信度 0–1 |
