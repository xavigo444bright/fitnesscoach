# UI / UX 规格说明

> 供设计与开发共用。PRD 需求 ID 以 `UI-xxx` 引用本文件。  
> **Agent**：实现 M3/M4/M5 前必须先读本文 + `docs/design-tokens.md`（MU 模块产出）。

## 1. UI 分三层（避免混在一起做）

| 层级 | 名称 | 做什么 | 在哪个模块做 |
|------|------|--------|--------------|
| **L1** | 设计基础 | 设计令牌、线框图、组件清单、平台差异 | **MU**（M0 后、M3 前） |
| **L2** | 训练叠加层 | 摄像头上的骨骼、ghost、反馈条、站位引导 | **M3** |
| **L3** | 应用页面层 | 动作库、详情、准备、总结等标准页面 | **M4 / M5** |

```
M0 基建
  ├─→ M1 Core（无 UI）
  └─→ MU 设计基础 ──┬─→ M3 叠加层 UI
                    └─→ M4/M5 页面层 UI
```

**关键结论**：UI **不是**等到 M4 才考虑。  
- **MU** 在 M1 同期定调性和布局原则  
- **M3** 做最核心的「训练中」体验（用户 80% 时间所在）  
- **M4/M5** 做壳子和流程页

#### PG-004 · FeedbackBar 状态（含「改正后」）

反馈条不仅报错，还要覆盖**同一 rep 内用户改正**后的正反馈与清空（产品批注 2026-07-18）。

| 状态 | 触发 | 条样式 / 文案示例 | 随后 |
|------|------|-------------------|------|
| **idle** | 无已确认错误；或正反馈已结束 | 条隐藏或空 | — |
| **correcting** | core 确认某规则（如 `knee-valgus-l`），经防抖 | 错误/警告色；纠错短句（≤20 字） | 保持至规则不再触发，或被更高优先级错误替换 |
| **recovered** | **同一错误在本轮动作中消失**（用户已改正，如内扣纠正） | 正确色；正反馈短句，如「很好，膝盖稳住了」 | 展示约 **1.5–2s** 后 → **清空回 idle**（勿无限挂着） |
| **multi** | 同时多个问题 | 最多 **2** 条；优先级 error > warning；同级按规则表顺序 | 某一条改正 → 该条走 recovered，另一条可仍 correcting |

**约束（实现落在 M3，对齐 FR-043 / 防抖冷却）：**

1. **改正必须有正反馈**：不能只从红字直接消失；至少短暂 `recovered`。
2. **改正后必须能清空**：`recovered` 超时后条清空，避免「已经改好了还一直显示内扣」。
3. **同错误冷却仍生效**：清空后若再次犯同一错，须重新满足防抖，且受 ≥2s 冷却约束（不刷屏）。
4. **以当前帧校验为准**：正反馈针对「刚消失的那条规则」，不是笼统「全部正确」才出现（允许仍有其他次要问题）。
5. 文案走 token / 规则 `message` 的「恢复」变体或统一轻量句；MVP 可用固定短句池按规则 ID 映射。

#### PG-004 · 布局分区（MU-T4 / UI-006）

竖屏全屏相机为底；叠加三层，互不抢触控（结束钮除外）：

```
┌─────────────────────────────┐  ← 屏幕顶（含刘海 / Dynamic Island）
│ ######## safe-area-top ##### │  ← 状态栏 inset；反馈条下沿须在此之下
├─────────────────────────────┤
│ [A] FeedbackBar             │  ← min-height token；最多 2 行；pointerEvents=box-none
│     （scrim + 文案）          │
├─────────────────────────────┤
│                             │
│ [B] Camera + Skeleton       │  ← 主视觉区，flex 1
│     + Ghost                 │     骨骼/ghost 不拦截手势
│                             │
├─────────────────────────────┤
│ [C] BottomBar  Rep | 结束   │  ← height token；「结束」触控 ≥44
├─────────────────────────────┤
│ #### safe-area-bottom ##### │  ← Home Indicator；底栏内容在此之上
└─────────────────────────────┘
```

| 区 | Token | 约束 |
|----|-------|------|
| A | `--feedback-bar-min-height` / `--color-overlay-scrim` | 不遮挡人脸关键区优先；过长文案截断 2 行 |
| B | `--ghost-opacity` | 全宽；与相机同坐标系 |
| C | `--bottom-bar-height` / `--touch-min` | 无 TabBar；结束为 Secondary/危险操作样式可后续定 |

## 5. 平台 UI 差异（MU-T5 / UI-010）

| 项 | App (RN) | 微信小程序 |
|----|----------|------------|
| 导航 | React Navigation stack | `wx.navigateTo` |
| 字体 | 系统默认 SF/Roboto | 微信默认字体 |
| 摄像头比例 | 全屏 `cover` | `camera` 组件固定比 |
| 顶部安全区 | `SafeAreaView` / `useSafeAreaInsets` | `menuButton` 下缘或 `statusBarHeight` |
| 底部安全区 | `SafeAreaView` | `env(safe-area-inset-bottom)` |
| 主按钮高度 | ≥48dp | ≥44px |
| 令牌消费 | `import { theme } from '@fitness-coach/ui'` | 同包或编译期拷贝 CSS 变量 |
| 叠加绘制 | RN Skia / Canvas（M3 定） | `canvas` / cover-view（M3/M5 定） |

MVP：**结构一致，允许像素级差异**；颜色/字号走同一套 token（`docs/design-tokens.md`）。  
训练页（PG-004）两端都必须保留 FeedbackBar 的 `correcting` / `recovered` / 清空行为，不得一端省略正反馈。

## 6. 交互与动效（MVP）

| ID | 行为 | 说明 |
|----|------|------|
| UX-001 | 反馈条入场 | 错误时自上而下 slide-in，200ms |
| UX-002 | 关节变色 | 150ms 颜色过渡，避免闪烁 |
| UX-003 | Rep +1 | 数字 scale 1.2→1.0，300ms |
| UX-004 | 倒计时 | 每秒切换，最后 1 秒略放大 |
| UX-005 | 改正正反馈 | 某错误消失 → `recovered` 正反馈 1.5–2s → 清空（见 PG-004 FeedbackBar） |
| UX-006 | 持续正确轻提示 | 可选：整段无错误连续 ≥2s 可再出轻量「很好」（弱于 UX-005，勿刷屏） |
| UX-007 | 有效 rep 打勾 | 计数 +1 时屏幕中央绿色 ✓ 弹出再淡出，~700ms（与 UX-003 同触发） |
| UX-008 | 上次问题回看 | 不标准 rep 固化错误原因；站起后可点「查看上次问题」；下一次有效 rep 出 recovered 正反馈后清空 |

## 7. 无障碍（MVP 最低线）

- 反馈**必须有文字**（FR-063），不能仅靠颜色
- 按钮触控区 ≥44pt
- 总结页数据用文本而非纯图标
